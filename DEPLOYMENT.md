# MedAssist — Production Deployment Guide

This guide outlines the recommended deployment architecture, configuration parameters, and manual deployment steps for MedAssist (HackXLerate 2026).

---

## 1. Recommended Deployment Architecture

MedAssist uses a decoupled modern web stack designed for low operational overhead, high security, and clear separation of concerns:

| Component | Technology | Recommended Host | Configuration / Command |
| :--- | :--- | :--- | :--- |
| **Frontend** | React 19 + Vite + Tailwind CSS | **Vercel** / **Netlify** / **Cloudflare Pages** | Build: `npm run build`<br>Output directory: `dist` |
| **Backend** | Python 3.11+ / FastAPI / Uvicorn | **Render** / **Railway** / **Fly.io** | Start command:<br>`uvicorn app.main:app --host 0.0.0.0 --port $PORT` |
| **Database & Storage** | PostgreSQL 15+ & S3 Storage | **Supabase** (Managed) | Schema: `database/schema.sql`<br>Private Bucket: `medical-documents` |
| **AI Intelligence** | Gemini 1.5 Flash | **Google AI Studio** | Server-side only key (`GEMINI_API_KEY`) |

## 2. Environment Variables Specification

> Secrets must NEVER be committed to Git. All `.env` files are excluded by `.gitignore`.

## 3. Database & Storage Preparation (Supabase)

1. **Apply Schema & Auth Migration:**
   - Navigate to **Supabase Dashboard** → **SQL Editor** → **New query**.
   - Copy and paste the contents of [`database/schema.sql`](file:///c:/Users/RAGHUPATHI/OneDrive/Desktop/HackXLerate/XLerate/database/schema.sql) (if setting up fresh) and [`database/migration_auth.sql`](file:///c:/Users/RAGHUPATHI/OneDrive/Desktop/HackXLerate/XLerate/database/migration_auth.sql).
   - Execute the script. This creates 8 health tables with Row Level Security (RLS) policies:
     `patients`, `documents`, `observations`, `medications`, `conditions`, `timeline_events`, `ai_conversations`, `ai_messages`.
2. **Private Storage Bucket:**
   - In Supabase Dashboard, go to **Storage** → **Buckets**.
   - Verify or create bucket: `medical-documents`.
   - Ensure **Public bucket** is toggled **OFF** (Private).
   - Documents are only accessed via signed short-lived URLs generated by the backend (`/api/documents/{id}/download`).

## 4. Manual Backend Deployment (e.g. Render / Railway)

1. Connect your repository to the hosting provider.
2. Set the root directory to `backend`.
3. Set the environment to **Python 3.11+**.
4. Configure Build and Start commands:
   - **Build Command:** `pip install -r requirements.txt`
   - **Start Command:** `uvicorn app.main:app --host 0.0.0.0 --port $PORT`
5. Add the Backend Environment Variables defined in Section 2.
6. Trigger manual deploy and verify health check at:
   `https://<your-backend-domain>/health`

---

## 5. Manual Frontend Deployment (e.g. Vercel)

1. Connect your repository to Vercel.
2. Set the root directory to `frontend`.
3. Framework Preset: **Vite**.
4. Configure Build and Output:
   - **Build Command:** `npm run build`
   - **Output Directory:** `dist`
5. Add Environment Variable:
   - `VITE_API_URL` = `https://<your-backend-domain>`
6. Deploy and verify that the dashboard and copilot connect to the backend.
